راهنمای کامل افزونه WordPress

اتصال بدون لاگین ایمیل/رمز در افزونه، ساخت کلید توسط پلاگین، تأیید در سایت دیلندر، احراز با Installation Key، و تبادل متن/عکس/ویدیو از طریق edit-session

۰. مدل جدید اتصال

  1. افزونه یک installationKey تصادفی می‌سازد (حداقل ۳۲ کاراکتر).
  2. افزونه درخواست اتصال به بک‌اند می‌فرستد (فقط هش کلید ذخیره می‌شود).
  3. افزونه تب دیلندر را با approveUrl باز می‌کند.
  4. کاربر در دیلندر لاگین می‌کند (اگر نبود) و اتصال را تأیید می‌کند.
  5. افزونه وضعیت را poll می‌کند تا APPROVED شود.
  6. از آن به بعد APIها با هدرهای Installation Key + Site URL صدا زده می‌شوند.
POST /api/v1/auth/wordpress/login حذف شده است. ایمیل و رمز کاربر را از فرم افزونه جمع نکنید.
اتصال برقرارشده انقضای اجباری ندارد. قطع اتصال از پنل دیلندر یا غیرفعال‌سازی/چرخش کلید انجام می‌شود. درخواست pending حدود ۱۵ دقیقه عمر دارد.

۱. تنظیمات پایه افزونه

define('DLANDER_API_URL', 'https://api.example.com'); // بدون اسلش انتهایی
define('DLANDER_PLUGIN_VERSION', '1.0.0');

مقادیر پیشنهادی در Options (رمزنگاری در صورت امکان):

dlander_installation_key
dlander_site_url
dlander_connected          // bool
dlander_wordpress_site_id  // اختیاری بعد از approve
dlander_last_request_id

۲. ساخت کلید نصب

function dlander_generate_installation_key(): string {
    return rtrim(strtr(base64_encode(random_bytes(32)), '+/', '-_'), '=');
}

$key = get_option('dlander_installation_key');
if (!$key) {
    $key = dlander_generate_installation_key();
    update_option('dlander_installation_key', $key, false);
}

۳. ایجاد درخواست اتصال

POST {DLANDER_API_URL}/api/v1/wordpress/connection-requests
Content-Type: application/json

{
  "siteUrl": "https://shop.example.com",
  "installationKey": "PLUGIN_GENERATED_KEY_32PLUS",
  "siteName": "فروشگاه من",
  "metadata": {
    "wpVersion": "6.8",
    "phpVersion": "8.3",
    "pluginVersion": "1.0.0",
    "multisite": false
  }
}
{
  "data": {
    "requestId": "uuid",
    "status": "PENDING",
    "domain": "shop.example.com",
    "expiresAt": "2026-08-19T12:15:00.000Z",
    "approveUrl": "https://dlander.com/connect/wordpress?requestId=uuid"
  },
  "meta": null
}
فقط metadata غیرحساس بفرستید. رمز DB، کلیدهای wp-config و secretها ممنوع است.

siteUrl می‌تواند لوکال باشد (http://localhost:8080)؛ بک‌اند فقط hostname را نرمال می‌کند.

نمونه PHP

$response = wp_remote_post(DLANDER_API_URL . '/api/v1/wordpress/connection-requests', [
    'timeout' => 20,
    'headers' => ['Content-Type' => 'application/json'],
    'body' => wp_json_encode([
        'siteUrl' => home_url(),
        'installationKey' => $key,
        'siteName' => get_bloginfo('name'),
        'metadata' => [
            'wpVersion' => get_bloginfo('version'),
            'phpVersion' => PHP_VERSION,
            'pluginVersion' => DLANDER_PLUGIN_VERSION,
        ],
    ]),
]);
$data = json_decode(wp_remote_retrieve_body($response), true)['data'];
update_option('dlander_last_request_id', $data['requestId'], false);
// باز کردن تب تأیید برای کاربر ادمین:
// window.open($data['approveUrl'], '_blank');

۴. Poll وضعیت تا تأیید

GET {DLANDER_API_URL}/api/v1/wordpress/connection-requests/{requestId}

وضعیت‌ها: PENDING | APPROVED | DENIED | EXPIRED

// هر ۲–۳ ثانیه تا APPROVED یا خطا
$status = $body['data']['status'];
if ($status === 'APPROVED') {
    update_option('dlander_connected', true, false);
    update_option('dlander_site_url', home_url(), false);
    if (!empty($body['data']['wordpressSiteId'])) {
        update_option('dlander_wordpress_site_id', $body['data']['wordpressSiteId'], false);
    }
}

اگر EXPIRED یا DENIED شد، درخواست جدید بسازید. UI باید بگوید کاربر در دیلندر باید لاگین/تأیید کند.

۵. احراز هویت API بعد از اتصال

X-Dlander-Installation-Key: PLUGIN_GENERATED_KEY
X-Dlander-Site-Url: https://shop.example.com

JWT وردپرس لازم نیست. Bearer وب هم از افزونه نفرستید مگر برای سناریوهای خاص فرانت.

function dlander_api_headers(): array {
    return [
        'Content-Type' => 'application/json',
        'X-Dlander-Installation-Key' => get_option('dlander_installation_key'),
        'X-Dlander-Site-Url' => home_url(),
    ];
}

خطاها: INVALID_INSTALLATION_KEY، SITE_DISABLED.

۶. شروع کار ادیت (متن / عکس / ویدیو)

۶.۱ ساخت جلسه

POST /api/v1/wordpress/edit-sessions
X-Dlander-Installation-Key: ...
X-Dlander-Site-Url: ...
Content-Type: application/json

{
  "inputText": "متن صفحه برای ویرایش",
  "inputJson": { "postId": 123, "field": "content" }
}

پاسخ شامل id، editorUrl، expiresAt است. editorUrl را برای کاربر ادمین باز کنید تا در دیلندر کار کند.

۶.۲ آپلود ورودی

POST /api/v1/wordpress/edit-sessions/{id}/assets
X-Dlander-Installation-Key: ...
X-Dlander-Site-Url: ...
Content-Type: multipart/form-data

file=@image.jpg
direction=input

مجاز: image/jpeg|png|webp|gif تا ۱۰MB و video/mp4|webm تا ۱۰۰MB.

۶.۳ گرفتن نتیجه

GET /api/v1/wordpress/edit-sessions/{id}/result
X-Dlander-Installation-Key: ...
X-Dlander-Site-Url: ...

وقتی وضعیت COMPLETED باشد، outputText / outputJson و assetهای خروجی با downloadUrl برمی‌گردند. می‌توانید قبل از complete با GET .../edit-sessions/{id} وضعیت را poll کنید.

۷. قطع اتصال و چرخش کلید

  • کاربر می‌تواند از پنل دیلندر سایت را Delete یا Disable کند → API افزونه با SITE_DISABLED / کلید نامعتبر شکست می‌خورد.
  • اگر از وب rotate-key زده شود، کلید قبلی باطل است؛ افزونه باید کلید جدید را از کاربر بگیرد یا دوباره connect کند.
  • پیشنهاد UX افزونه: دکمه «قطع اتصال محلی» که Options را پاک کند و دکمه «اتصال مجدد به دیلندر» که flow بخش ۳ را از نو اجرا کند.

۸. چند دامنه / لوکال

هر نصب وردپرس (هر دامنه یا localhost) flow اتصال خودش را دارد. یک اکانت دیلندر می‌تواند چند سایت متصل داشته باشد. دامنه در بک‌اند نرمال می‌شود؛ مسیر و پروتکل در هویت نصب دخیل نیستند.

۹. امنیت

  • کلید خام فقط در افزونه؛ در API فقط هش ذخیره می‌شود.
  • تأیید اتصال فقط با نشست وب کاربر در دیلندر.
  • درخواست pending کوتاه‌عمر است.
  • Rate limit روی create/poll اعمال می‌شود.
  • هرگز access/refresh وب کاربر را در وردپرس ذخیره نکنید مگر نیاز صریح محصول.

۱۰. چک‌لیست پیاده‌سازی افزونه

  • تولید و ذخیره امن installation key
  • create connection-request + باز کردن approveUrl
  • poll تا APPROVED / نمایش خطاهای DENIED و EXPIRED
  • فراخوانی API با دو هدر Installation
  • edit-session + آپلود asset + باز کردن editorUrl + دریافت result
  • UI اتصال مجدد پس از disable/rotate
  • حذف وابستگی به /auth/wordpress/login
