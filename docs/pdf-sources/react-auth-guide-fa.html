۰. نقش فرانت در اکوسیستم

فرانت React همان اپلیکیشن دیلندر است که کاربر در مرورگر با آن کار می‌کند. افزونه وردپرس دیگر با ایمیل/رمز جدا لاگین نمی‌کند؛ به‌جای آن یک تب از دیلندر باز می‌کند تا کاربر همان اکانت وب را تأیید کند.

کارمسئول
ثبت‌نام / لاگین / refresh / logoutفرانت (نشست WEB)
صفحه تأیید اتصال وردپرسفرانت: /connect/wordpress?requestId=...
مدیریت سایت‌های متصلفرانت با Bearer وب
ادیت محتوای ارسالی از وردپرسفرانت: /editor/wordpress?sessionId=...
ساخت کلید نصب و poll اتصالافزونه وردپرس (نه فرانت)
فرانت هرگز به هدرهای X-Dlander-Installation-Key و X-Dlander-Site-Url نیاز ندارد. آن‌ها فقط برای افزونه هستند.

چند مرورگر/دستگاه هم‌زمان مجاز است؛ هر لاگین یک نشست WEB جدید می‌سازد.

۵. صفحه تأیید اتصال وردپرس (الزامی برای محصول جدید)

مسیر پیشنهادی فرانت:

/connect/wordpress?requestId=<UUID>

این URL را بک‌اند در فیلد approveUrl هنگام ساخت درخواست اتصال برمی‌گرداند و افزونه آن را در تب/پاپ‌آپ باز می‌کند.

۵.۱ جریان UX

  1. خواندن requestId از query string
  2. اگر کاربر لاگین وب ندارد → هدایت به لاگین با returnUrl به همین صفحه
  3. دریافت جزئیات درخواست (عمومی):
GET /api/v1/wordpress/connection-requests/:requestId
{
  "data": {
    "requestId": "...",
    "domain": "shop.example.com",
    "siteName": "فروشگاه من",
    "status": "PENDING",
    "expiresAt": "2026-08-19T12:15:00.000Z",
    "wordpressSiteId": null,
    "createdAt": "..."
  },
  "meta": null
}
  1. نمایش ایمیل اکانت فعلی (GET /users/me) + دامنه درخواست
  2. دکمه تأیید یا رد

۵.۲ تأیید / رد

POST /api/v1/wordpress/connection-requests/:requestId/approve
Authorization: Bearer ACCESS_TOKEN

POST /api/v1/wordpress/connection-requests/:requestId/deny
Authorization: Bearer ACCESS_TOKEN

فقط نشست client=web مجاز است. پس از approve موفق، پیام «اتصال برقرار شد؛ می‌توانید این تب را ببندید» نشان دهید.

درخواست pending حدود ۱۵ دقیقه اعتبار دارد. وضعیت‌ها: PENDING، APPROVED، DENIED، EXPIRED.

خطاهای مهم: CONNECTION_REQUEST_EXPIRED، CONNECTION_REQUEST_DENIED، CONNECTION_REQUEST_NOT_FOUND، CONNECTION_REQUEST_NOT_PENDING.

۶. مدیریت سایت‌های متصل (پنل کاربر)

عملEndpoint
فهرستGET /api/v1/users/me/wordpress-sites
نام / فعال‌سازیPATCH .../:id با { "name"?, "enabled"? }
قطع اتصالDELETE .../:id
چرخش کلیدPOST .../:id/rotate-key → یک‌بار installationKey خام
تغییر دامنه از PATCH انجام نمی‌شود. برای دامنه جدید، افزونه باید دوباره flow اتصال را اجرا کند. اتصال برقرارشده انقضای اجباری ندارد.

اگر کاربر rotate-key بزند، کلید قبلی باطل می‌شود و باید کلید جدید را در تنظیمات افزونه جایگزین کند (یا دوباره connect کند).

۷. صفحه ادیتور وردپرس

مسیر پیشنهادی:

/editor/wordpress?sessionId=<UUID>

افزونه پس از ساخت edit-session لینک editorUrl را باز می‌کند. کاربر باید با نشست وب لاگین باشد.

۷.۱ خواندن جلسه

GET /api/v1/wordpress/edit-sessions/:sessionId
Authorization: Bearer ACCESS_TOKEN

پاسخ شامل inputText / inputJson، وضعیت، assets[] با downloadUrl، و editorUrl است.

۷.۲ ذخیره نتیجه

POST /api/v1/wordpress/edit-sessions/:sessionId/complete
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json

{
  "outputText": "متن نهایی",
  "outputJson": { "blocks": [] }
}

۷.۳ آپلود خروجی مدیا از ادیتور

POST /api/v1/wordpress/edit-sessions/:sessionId/output-assets
Authorization: Bearer ACCESS_TOKEN
Content-Type: multipart/form-data

file: <binary>

انواع مجاز: jpeg/png/webp/gif تا ۱۰MB و mp4/webm تا ۱۰۰MB.

خطاها: EDIT_SESSION_EXPIRED، EDIT_SESSION_ALREADY_COMPLETED، UNSUPPORTED_MEDIA، FILE_TOO_LARGE.

۸. الگوی پیشنهادی React برای صفحه Connect

async function loadConnectionRequest(requestId, accessToken) {
  if (!accessToken) {
    redirectToLogin(`/connect/wordpress?requestId=${requestId}`);
    return;
  }
  const res = await fetch(`/api/v1/wordpress/connection-requests/${requestId}`);
  const body = await res.json();
  if (!res.ok) throw body.error;
  return body.data; // domain, siteName, status, expiresAt
}

async function approveConnection(requestId, accessToken) {
  const res = await fetch(
    `/api/v1/wordpress/connection-requests/${requestId}/approve`,
    { method: 'POST', headers: { Authorization: `Bearer ${accessToken}` } },
  );
  const body = await res.json();
  if (!res.ok) throw body.error;
  return body.data;
}

۹. امنیت و CORS برای فرانت

مدل: JWT کوتاه‌عمر + نشست قابل‌ابطال در DB + refresh rotation + کپچای تطبیقی + rate limit. اتصال وردپرس فقط با تأیید نشست وب کامل می‌شود.
FRONTEND_URL=https://dlander.com
CORS_ORIGINS=http://localhost:5173,https://dlander.com
  • CORS فقط برای originهای فرانت است؛ افزونه سروربه‌سرور است و به CORS وابسته نیست.
  • استفاده از دیلندر بدون وردپرس کاملاً مستقل می‌ماند.
  • POST /api/v1/auth/wordpress/login حذف شده؛ فرانت نباید به آن وابسته باشد.

۱۰. چک‌لیست پیاده‌سازی فرانت

  • لاگین / refresh / logout / captcha
  • صفحه /connect/wordpress با approve/deny
  • بازگشت بعد از لاگین به همان requestId
  • لیست سایت‌های متصل + disconnect + disable + rotate-key UI
  • صفحه /editor/wordpress با complete و output-assets
  • عدم ارسال هدرهای Installation به API از فرانت
